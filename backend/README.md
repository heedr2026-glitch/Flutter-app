# خادم خدووم

خادم REST مبني بـ Python وSQLite دون مكتبات إضافية، ومجهز للتشغيل المحلي أو داخل Docker.

## التشغيل

```powershell
python server.py
```

ثم افتح `http://127.0.0.1:8080/health`.

لوحة المالك: `http://127.0.0.1:8080/owner`

مفتاح المالك يُنشأ تلقائيًا في `backend/owner.key`. لا تشاركه مع أي مشترك.

## المتوفر

- تسجيل مؤسسة ومدير وتسجيل الدخول.
- كلمات مرور PBKDF2 مع salt منفصل.
- جلسات دخول عشوائية تنتهي بعد 30 يومًا.
- عزل بيانات كل مؤسسة.
- جداول المستخدمين والموظفين والمركبات والاشتراكات والإعلانات.
- واجهات المؤسسة والمركبات وإعلانات VIP.
- لوحة مالك لإنشاء أكواد BASIC وVIP وتغيير باقة أي مؤسسة.
- كود التفعيل له مدة وعدد استخدامات وتاريخ انتهاء.

قبل الإنتاج يجب تشغيله خلف HTTPS، ونقل SQLite إلى PostgreSQL، وضبط النسخ الاحتياطي، وربط OTP والدفع.

## النشر

- ملف `Dockerfile` يشغّل الخادم على المنفذ الذي توفره منصة الاستضافة.
- عيّن `KHDOOM_OWNER_KEY` كمتغير سري ولا تضعه داخل الكود.
- اربط قرصًا دائمًا على `/data` واضبط `KHDOOM_DB=/data/khdoom.db`.
- ملف `render.yaml` جاهز لإنشاء خدمة بخادم وقرص دائم على Render.
- بعد النشر غيّر `cloud_api_url` في التطبيق إلى رابط HTTPS العام ثم ابنِ نسخة جديدة.

## تفعيل موظفي AI

أضف المتغيرات السرية التالية في منصة استضافة الخادم، ولا تضع المفتاح داخل Flutter أو APK:

- `OPENAI_API_KEY`: مفتاح OpenAI السري، ويوضع في الخادم فقط.

يستخدم `ai_core.py` نموذج `gpt-5.6-sol` حصرا عبر Responses API. جميع موظفي AI
يمرون بالخدمة المركزية نفسها، مع أدوات وصلاحيات مختلفة لكل دور وفصل البيانات
باستخدام `company_id`.

بعد حفظ المتغيرات أعد نشر الخادم. نقطة التقرير الذكي هي:

`POST /api/ai/commercial-report`

وتتطلب جلسة دخول صالحة. حدود الاستخدام اليومية: 5 للمجانية، و30 للأساسية، و100 لـ VIP. إذا كانت خدمة AI غير متاحة، يستخدم التطبيق التقرير المحلي تلقائيًا.
